# 배포 버전별 참가자 파일

이미지를 새로 발행했을 때 참가자에게 이전 ZIP이 섞여 나가지 않도록 릴리스에 파일 선택을 저장합니다
이미지 발행번호와 ZIP 발행번호는 화면에서 따로 표시합니다

관리자는 문제 목록 → 설정 열기 → 배포 설정 → 참가자 파일에서 연결 방식을 고릅니다

| 연결 방식 | 동작 |
| --- | --- |
| 같은 발행본 자동 연결 | 이미지와 registry_revision이 같은 ZIP 사용, 아직 수집되지 않았으면 대기 |
| 등록된 ZIP 직접 선택 | 같은 문제에 등록된 ZIP 하나를 선택, 이미지와 발행번호가 다르면 화면에 안내 |
| 파일 없음 | 이 설정 버전에서는 참가자 첨부파일을 제공하지 않음 |

저장하면 기존 이미지·포트·자원·환경변수·비밀값 버전을 복사한 새 릴리스가 생깁니다
저장만으로 현재 적용 버전은 바뀌지 않습니다
이 버전 사용을 누르면 새 인스턴스와 아직 실행하지 않은 참가자에게 적용됩니다
이전 버전을 다시 적용하면 파일 연결도 그 버전으로 돌아갑니다
이미 실행 중인 참가자는 생성 당시 릴리스에 연결된 파일을 계속 받습니다

환경변수 수정이나 .env 가져오기로 만든 릴리스는 원본의 파일 선택도 이어받습니다
CI에서 새로 발행한 이미지의 릴리스는 같은 발행본 자동 연결로 시작합니다
파일 없음으로 발행된 기록과 아직 수집되지 않은 상태를 구분하며, 다른 발행번호의 최신 ZIP으로 대체하지 않습니다
기존 릴리스는 마이그레이션 후에도 같은 발행본 자동 연결을 사용합니다

## API

| API | 용도 |
| --- | --- |
| GET /api/v1/admin/challenges/{challenge_id}/files?release_id={release_id} | 선택한 배포 버전의 ZIP, 같은 발행본, 다른 파일 목록 확인 |
| POST /api/v1/admin/challenges/{challenge_id}/releases/{release_id}/files | 원본 릴리스에서 파일 선택만 바꾼 새 버전 저장 |

두 API는 관리자만 사용할 수 있고 응답을 캐시하지 않습니다
조회에서 release_id를 생략하면 현재 적용 버전을 반환합니다
다른 파일 목록은 page로 20건씩 조회하며 history_next_page가 없으면 마지막 페이지입니다
저장 요청은 mode와 선택 시 file_id만 받습니다
이미지나 환경변수를 함께 바꿀 수는 없습니다
같은 Idempotency-Key와 같은 내용으로 재시도하면 처음 생성한 버전을 반환하며, 내용이 다르면 409를 반환합니다

릴리스 응답의 user_files에는 mode, status, file, matches_image_revision이 포함됩니다
status는 available, pending, none, disabled, unavailable을 구분합니다
available은 파일 저장 기록이 있다는 뜻이며 실제 저장소 접근 가능 여부는 다운로드 때 확인합니다
선택된 ZIP은 참조하는 릴리스가 남아 있는 동안 개별 삭제할 수 없습니다

## 파일 수집 실패

GCS나 로컬 파일 저장소에서 오류가 나면 해당 파일을 미처리 상태로 남기고 다음 파일을 수집합니다
다음 수집 주기에 실패한 파일을 다시 시도하며, GCS 권한·인증 오류는 운영자가 설정을 복구한 뒤 재시도할 수 있습니다
저장 실패 로그에는 파일 발행 이름과 오류 종류만 남깁니다
저장소 오류 때문에 현재 적용 버전이나 이미 등록된 ZIP을 바꾸지는 않습니다
